# 작은 모델이 요약 규칙을 통째로 무시한 문제

- 발견: 2026-08-18 (요약 규칙을 넣은 뒤 티어별 점수를 다시 보다가)
- 증상: 같은 규칙을 넣었는데 hf 는 좋아지고 ollama 만 0.345 에서 0.151 로 떨어졌다
- 상태: 해결. 같은 요구를 JSON 스키마 값 자리에도 적어 hf 0.808 / ollama 0.496

## 증상

summary 규칙 5줄을 프롬프트에 붙인 뒤 티어별 요약 충실도가 이렇게 갈렸다.

```
auto     0.526 -> 0.835
ollama   0.345 -> 0.151
rule     0.056 -> 0.056  (대조군, 안 움직임)
```

프롬프트 하나를 세 티어가 같이 쓰는데 한쪽만 반대로 갔다.

## 첫 가설은 틀렸다

"프롬프트가 길어져서 작은 모델이 버거워졌다"고 적어뒀다. 그럴듯했지만 확인은
안 한 상태였고, 결과적으로 **원인을 절반만 짚은 것이었다.**

길이가 문제였다면 규칙을 짧게 줄이는 것으로 끝났어야 하는데, 실제로는 길이를
거의 그대로 두고 위치만 바꿔도 고쳐졌다.

## 확인한 순서

### 1. 폴백 오염부터 걷어냈다

이전에 같은 자리에서 데인 적이 있어서(`2026-08-17-폴백이-측정에-섞여-유령-0점이-나온-문제.md`)
먼저 확인했다. 29절에서 붙여둔 `analysis_provider` 로 12건 전부 `tier=ollama`
였다. ollama 가 실제로 그 점수를 받은 게 맞았다.

### 2. 숫자 말고 요약문을 봤다

```
[unassigned-01] OCI 배포 점검 회의
[unassigned-02] 스프린트 회고 회의
[formal-01] RAG 재색인 점검 회의
[nosep-01] 알림 중복 제거 회의
```

전부 제목만 되풀이한 요약이다. 그런데 이 형태는 내가 쓴 규칙 2번이 나쁜 예로
콕 집어 금지한 것이다. **규칙을 못 지킨 게 아니라 안 읽은 쪽에 가깝다.**

모델은 `qwen2.5:1.5b`, 프롬프트는 3,826자에 규칙 블록이 6개였다.

### 3. 위치만 바꿔서 갈랐다

같은 6건에 세 변형을 돌렸다.

| 변형 | 규칙 위치 | 제목만 쓴 건수 |
|---|---|---|
| A | 스키마와 떨어진 별도 블록 5줄 | 5/6 |
| B | 없음 | 4/6 |
| C | 스키마의 `"summary"` 값 자리 한 줄 | 0/6 |

## 원인

- 표면: 1.5B 모델이 summary 규칙 블록을 반영하지 않았다
- 근본: 규칙이 채워야 할 필드에서 멀리 떨어진 자리에 있었다. 작은 모델은 칸 옆에
  적힌 지시를 따르고, 멀리 있는 블록은 사실상 흘린다

길이 자체는 부차적이었다. C 변형의 프롬프트는 3,332자로 A(3,826자)보다 500자
짧을 뿐인데 결과는 5/6 에서 0/6 으로 갈렸다.

## 시도했지만 안 된 것

### 규칙을 스키마 줄로만 옮기기

ollama 는 0.530 으로 올랐는데 hf 가 0.803 에서 0.669 로 떨어졌다. 내려간 5건이
전부 1.000 에서 0.667 이라 우연이 아니었고, 빠진 문항이 전부 배경이었다. 한 줄로
줄이면서 "왜 이 논의를 했는지"를 빼먹은 것이 그대로 찍혔다.

### 배경을 넣어 한 줄로 버티기

hf 0.728 까지 회복했지만 0.803 에는 못 미쳤다. 노이즈인지 확인하려고 같은 설정을
3회 반복했다.

```
회차1 0.756 / 회차2 0.756 / 회차3 0.784   폭 0.028
```

폭이 0.028 이라 0.07 차이는 실제였다. 큰 모델은 긴 블록이 있는 쪽이 낫다.

## 해결

티어별로 프롬프트를 나누려다가, 그 전에 **둘 다 두는 안**을 재봤다.

```
스키마 줄 + 규칙 블록  ->  hf 0.808 / ollama 0.496
```

양쪽 다 최고였다. 티어를 안 나누고 프롬프트 하나로 끝냈다. 같은 말을 두 군데
적는 게 중복처럼 보이지만, 읽는 모델이 둘이라 중복이 아니다.

캐시 스키마를 v5 로 올렸다. 캐시 키에 프롬프트가 안 들어가서, 안 올리면 작은
모델이 제목만 쓴 요약이 계속 나간다.

## 검증

- 폴백 제외 티어별 충실도: hf 0.808, ollama 0.496, rule_based 0.056
- 대조군(rule_based)이 네 회차 내내 0.056 으로 붙어 있다. 계측기가 아니라 대상만 바뀌었다
- To-Do f1 은 auto 1.000 으로 그대로. 요약을 고치면서 추출이 나빠지지 않았다
- 테스트 70건 통과

## 추후 관리

- ollama 0.496 은 여전히 낮다. 1.5B 한계인지 더 손볼 여지가 있는지는 안 갈랐다
- 모델을 바꾸면 이 배치가 다시 최적이라는 보장이 없다. 티어를 바꿀 때 다시 재야 한다

## 배운 점

- 프롬프트를 여러 모델이 나눠 쓰면, 한 프롬프트 수정이 티어마다 반대로 갈릴 수 있다.
  평균 하나만 보면 한쪽이 망가진 걸 못 본다
- 점수가 왜 내려갔는지는 점수를 더 봐도 안 나온다. 출력물을 직접 읽어야 한다
- 회차 간 흔들림 폭을 먼저 재두면 0.05 차이를 개선으로 읽을지 노이즈로 읽을지 안 헷갈린다
